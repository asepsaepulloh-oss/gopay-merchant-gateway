Autentikasi & Integrasi API Key

Setiap request ke API sistem (misalnya untuk generate QRIS dinamis) wajib menyertakan kredensial API Key merchant di dalam header HTTP request berikut untuk menjamin keamanan autentikasi:

x-api-key: [Public API Key Anda (pk_...)]
x-secret-key: [Secret API Key Anda (sk_...)]
Keamanan Kunci Rahasia: Kunci Rahasia (`x-secret-key`) dienkripsi di server menggunakan hash Bcrypt yang sangat aman. Jangan pernah membagikan atau membocorkan kunci rahasia ini di kode client-side (frontend) Anda. Selalu lakukan request API dari server backend Anda.
Isolasi Multi-Merchant (Pencegahan Tabrakan Transaksi)

Untuk memastikan transaksi antar merchant bekerja secara independen tanpa risiko saling menimpa satu sama lain, sistem kami menerapkan mekanisme isolasi data berikut:

  • Identifikasi Berdasarkan Kunci: Setiap request API diverifikasi secara aman menggunakan pasangan kunci. Server otomatis memetakan transaksi ke ID Merchant yang unik dan menyimpannya secara terisolasi.
  • Isolasi Webhook Forwarder: Tautan target forwarder HP Anda memiliki parameter ID khusus, yaitu /api/webhook/payment/[MERCHANT_ID]. Hal ini menjamin bahwa notifikasi e-wallet dari ponsel Anda hanya akan dicocokkan dengan transaksi pending milik akun merchant Anda sendiri, bukan milik merchant lain.
  • Duplikasi Nominal Aman: Bahkan jika dua merchant berbeda membuat tagihan dengan nominal dasar yang sama persis di detik yang sama, sistem tidak akan mengalami tabrakan data (collision) karena sistem memisahkan pencarian status berdasarkan filter ID Merchant yang terisolasi.

Siklus Hidup & Status Pembayaran

Sistem payment gateway ini menggunakan siklus hidup transaksi dengan status berikut:

PENDING

Transaksi baru saja dibuat dan menunggu pembayaran dari pelanggan. Pelanggan wajib membayar nominal persis (termasuk 3 digit unik di belakang) sebelum masa kadaluwarsa habis.

PAID

Pembayaran berhasil dicocokkan (melalui notifikasi forwarder) atau transaksi tidak terduga berhasil dimasukkan. Sistem secara **otomatis & real-time** memicu pengiriman callback webhook ke server Anda.

CANCELLED

Transaksi dibatalkan secara manual oleh merchant atau kedaluwarsa secara otomatis oleh sistem setelah melewati batas menit masa aktif yang diatur pada Pengaturan SaaS.

POST /api/payment/generate-qris

Membuat tagihan QRIS dinamis baru dengan sistem kode unik acak otomatis. Dana pembayaran langsung dialokasikan 100% ke akun QRIS merchant bersangkutan.

Request Body (JSON)
{
  "amount": 100000,
  "referenceId": "INV-9921820",
  "codeLen": 3 // Opsional: 2, 3, atau 4 digit (override setting global)
}
Response Sukses (JSON)
{
  "success": true,
  "trxId": "d3b07384-d113-4a1d-a5a6-0f72fbc62744",
  "referenceId": "INV-9921820",
  "amountBase": 100000,
  "uniqueCode": 247,
  "totalAmount": 100247,
  "qrisString": "00020101021226610014COM...",
  "qrisImage": "data:image/png;base64,iVBORw0..."
}
Contoh Integrasi Kode
const fetch = require('node-fetch');

async function createInvoice() {
    const res = await fetch('https://gateway.com/api/payment/generate-qris', {
        method: 'POST',
        headers: {
            'Content-Type': 'application/json',
            'x-api-key': 'pk_your_public_key',
            'x-secret-key': 'sk_your_secret_key'
        },
        body: JSON.stringify({
            amount: 100000,
            referenceId: 'INV-9921820'
        })
    });
    const data = await res.json();
    if (data.success) {
        console.log("QRIS dinamis dibuat:", data.qrisString);
        // Tampilkan gambar base64 di HTML:
        // imgElement.src = data.qrisImage;
    }
}

GET /api/payment/check

Memeriksa status pembayaran dari invoice transaksi menggunakan `trxId` yang didapatkan dari generate-qris.

Query Parameters
GET /api/payment/check?trxId=d3b07384-d113-4a1d-a5a6-0f72fbc62744
Response (JSON)
{
  "success": true,
  "status": "PAID", -- PENDING, PAID, CANCELLED
  "trxId": "d3b07384-d113-4a1d-a5a6-0f72fbc62744",
  "referenceId": "INV-9921820",
  "amountBase": 100000,
  "uniqueCode": 247,
  "totalAmount": 100247,
  "paidAt": "2026-07-11T12:00:15.000Z"
}
Contoh Real-time Polling (JavaScript)
function checkStatus(trxId) {
    const interval = setInterval(async () => {
        const res = await fetch(`/api/payment/check?trxId=${trxId}`);
        const data = await res.json();
        
        if (data.success) {
            if (data.status === 'PAID') {
                clearInterval(interval);
                alert("Pembayaran lunas! Layanan diaktifkan.");
                window.location.href = "/thank-you";
            } else if (data.status === 'CANCELLED') {
                clearInterval(interval);
                alert("Transaksi dibatalkan.");
            }
        }
    }, 3000); // Polling per 3 detik
}

Webhook Callback & Signature HMAC

Begitu transaksi dinyatakan sukses atau lunas (status berubah menjadi PAID), server payment gateway kami akan secara **otomatis dan real-time** mengirimkan callback berupa HTTP POST request dengan format JSON ke URL Webhook target yang telah Anda konfigurasikan di Dashboard.

Payload Webhook (JSON)
{
  "transaction_id": "d3b07384-d113-4a1d-a5a6-0f72fbc62744",
  "merchant_id": "8b08216c-31a2-4a0b-99d9-291efab9a771",
  "amount": 100000,
  "status": "PAID",
  "payment_method": "QRIS",
  "reference": "INV-9921820",
  "paid_at": "2026-07-11T12:00:15.000Z",
  "signature": "29acb162fca66e85e2b0..."
}
Verifikasi Signature HMAC SHA256 (Server Anda)
<?php
$secretKey = 'your_webhook_secret_key'; // Dari dashboard

// Ambil input JSON dari request
$inputRaw = file_get_contents('php://input');
$payload = json_decode($inputRaw, true);

$receivedSignature = $payload['signature'];
// Hapus parameter signature sebelum menghitung hash
unset($payload['signature']);

$calculatedSignature = hash_hmac('sha256', json_encode($payload, JSON_UNESCAPED_SLASHES), $secretKey);

if (hash_equals($calculatedSignature, $receivedSignature)) {
    // Tanda tangan valid! Proses order merchant Anda aman
    http_response_code(200);
    echo "Webhook diproses.";
} else {
    // Tanda tangan palsu/tidak valid
    http_response_code(400);
    echo "Signature Invalid.";
}
?>
const crypto = require('crypto');

app.post('/webhook-handler', (req, res) => {
    const secretKey = 'your_webhook_secret_key';
    const payload = req.body;
    
    const receivedSignature = payload.signature;
    delete payload.signature;
    
    const calculatedSignature = crypto
        .createHmac('sha256', secretKey)
        .update(JSON.stringify(payload))
        .digest('hex');
        
    if (calculatedSignature === receivedSignature) {
        // Valid!
        res.status(200).send('SUCCESS');
    } else {
        res.status(400).send('Signature Invalid');
    }
});

Integrasi Aplikasi Forwarder Notifikasi Android

Sistem ini membutuhkan aplikasi perantara di ponsel Android Anda untuk memforward notifikasi pembayaran (GoPay, OVO, DANA, SeaBank, dll.) secara real-time ke server gateway Anda.

Metode 1: Mengirimkan Payload via POST (JSON)
URL Endpoint Target:
POST https://[domain_anda]/api/webhook/payment/[MERCHANT_ID]

Ganti `[MERCHANT_ID]` dengan ID Merchant khusus Anda. Payload JSON wajib dikirimkan dengan struktur berikut:

{
  "title": "Pembayaran Berhasil",
  "text": "GoPay Rp 15.000 dari John Doe",
  "timestamp": 1718100250000
}
Metode 2: Mengirimkan Payload via GET (Query String)

Jika aplikasi forwarder Anda dikonfigurasi untuk mengirim request metode GET, gunakan format URL berikut:

URL Endpoint Target:
GET https://[domain_anda]/api/webhook/payment/[MERCHANT_ID]?name=[E_WALLET_NAME]&pkg=[PACKAGE_NAME]&text=[MESSAGE_CONTENT]&sign=[SIGNATURE]
Penjelasan Parameter Query GET:
  • name: Nama aplikasi e-wallet (contoh: dana, ovo, gopay, seabank).
  • pkg: Nama package Android (contoh: id.dana, ovo.id, com.gojek.gopay, id.co.bankbkemobile.digitalbank).
  • text: Isi pesan SMS atau notifikasi pembayaran (contoh: baru saja Kirim DANA ke kamu Rp50.000).
  • sign: Tanda pengenal/signature keamanan webhook (wajib bernilai: h3ruc0d3).
Sistem gateway akan mengekstrak nominal terkecil yang berawalan Rp dari parameter pesan notifikasi secara otomatis demi menghindari duplikasi saldo baru, lalu mencocokkannya ke database secara instan dan mengubah status transaksi menjadi PAID secara real-time.
